My Original Plans and Intentions

My original plan was to take the three artifacts I had already worked on and build on them using what I learned throughout my education. I focused on enhancing their current functionality. For the API, I wanted to improve validation, security, and testing. For the binary search tree, I wanted to improve how records were organized and retrieved by introducing a self-balancing structure. For the animal shelter dashboard, I wanted to improve database operations, filtering, and the way information was displayed. As I worked through each project, I had to adjust my plans based on the existing code, the issues I found during testing, and the time available. Some planned improvements were completed, while others remain areas I would like to continue working on.

1. Software Design & Engineering

I chose the Java Spring Boot REST service because I wanted to understand API communication, testing, and security in greater detail. APIs are important to the type of enterprise and cloud work I want to continue doing because they allow applications to exchange information. My original plan was to expand the existing service with stronger input validation, better error handling, additional automated tests, and a new transaction validation endpoint. I also wanted to explore secure communication and how different security practices fit into the development process. I completed improvements to the existing hash endpoint, added validation for blank input and requests exceeding the 256-character limit, improved the handling of invalid requests, and added HTML escaping. I also expanded automated testing to cover normal requests, invalid input, oversized input, HTML-related input, and SHA-256 hashing. I tested the endpoint through HTTPS using a browser as the client. I did not complete a separate client application or the planned transaction endpoint, and I still want more experience reviewing dependency vulnerabilities and conducting root cause analysis. I chose this artifact because it gave me a practical way to improve an existing application while learning more about reliability, security, and how applications communicate.

2. Algorithms & Data Structures

I chose the C++ binary search tree because I wanted to understand how data structures affect the way information is stored, searched, and managed. The original program uses bid information and supports inserting, searching, removing, and displaying records. My original plan was to convert the tree into an AVL tree, improve duplicate handling, and compare its performance against the original tree and a hash table. I implemented AVL balancing functionality using height calculations and left, right, left-right, and right-left rotations. I also worked on duplicate handling so updated bid information could replace existing records. These changes required additional attention to insertion, removal, node relationships, and maintaining balance as the data changed. I chose this artifact because it allowed me to work directly with the logic behind data organization and to show my skills for filtering data.

3. Database Development and Application Integration

I chose the Animal Dashboard artifact to showcase my skills between the Database layer and the UI. My original plan was to improve validation and error handling in the CRUD module, use MongoDB aggregation pipelines for appropriate filtering and summarizing operations, and keep the database functionality separate from the dashboard. I also considered adding a controlled natural-language query feature that could translate simple user questions into approved database queries. I worked on the CRUD functionality, dashboard layout, filtering options, and chart presentation. My intention was to add additonal security through the CRUD functionality. I also chose to clean up the pie chart and table so that the filtering added more value. I chose this artifact because it helped me understand how database operations, application logic, and the user interface need to work together to provide accurate and useful information. It also showcased my skills and understanding between mulitple layers.

While I had anticipated many changes, I focused on changes I could implement and test within my limitations.

What I Actually Enhanced

My completed enhancements focused on improving the functionality that was already there and addressing existing issues while reviewing and testing the projects. I wanted to make changes that had a clear purpose and helped me build on what I already knew. The API work gave me more experience with validation, testing, and secure request handling. 1. Software Design & Engineering

I enhanced my Java Spring Boot REST service by improving the existing hash endpoint and expanding its input handling and testing. The endpoint can accept custom information while retaining its default input when no parameter is provided. I added checks for blank input and requests longer than 256 characters, improved responses to invalid requests, and escaped HTML-related characters before displaying submitted information in the response. I also expanded automated tests to cover normal requests, invalid input, oversized input, HTML-related input, and SHA-256 hashing. These changes helped me better understand how an API receives information, handles unexpected input, and returns a response. I chose these enhancements because input validation and testing are important when applications exchange information, especially in enterprise environments where reliability and security matter.

Completed work and remaining improvements: The enhanced artifact shows how REST endpoint functionality, request validation, error handling, SHA-256 hashing, HTTPS testing, and expanded automated tests. I also reviewed the Maven configuration and the security tools used in the original project. I did not complete a separate client application or the planned transaction endpoint. I also want to continue improving my ability to analyze dependency vulnerabilities and investigate the root causes of application issues.

2. Algorithms & Data Structures

I enhanced the original binary search tree by implementing AVL tree balancing functionality. A standard binary search tree can become unbalanced depending on the order in which records are inserted. When this happens, searching can become less efficient because the tree may behave more like a linked list. I added height and balance calculations and implemented the rotations needed to maintain the AVL structure. I also worked on duplicate handling so updated bid information could replace existing records instead of creating unnecessary duplicates. I chose these changes because I wanted to address a limitation in the original data structure and understand the additional logic required to keep data organized as records are added or removed.

Completed work and remaining improvements: The development process gave me experience with recursion, node relationships, rotations, insertion, and removal. Completing benchmarks with the same datasets would help me understand how their performance compares and provide measurable results to support decisions related to volume.

3. Database Development and Application Integration

I enhanced the animal shelter dashboard by focusing on the filtering logic, CRUD functionality, layout, and the way information is displayed. I wanted the dashboard to concentrate on cats and dogs, provide more useful filtering options, and present results through a clearer table and pie chart. Since I wanted to keep the existing database records unchanged, the improvements focused on the application code responsible for retrieving, processing, and displaying the information. I chose these changes because database integration is not just about connecting an application to a data source. The results also need to be filtered correctly and presented in a way that makes sense to the user.

Completed work and remaining improvements: I focused on making the cat and dog categories easier to understand and improving how the displayed results are presented. Some filtering behavior still needs correction, its not a simple selection dropdown. I will continue improving my skills with validation and error handling in the database layer.

I chose these enhancements because they allowed me to build on existing projects while developing technical skills that connect to my interests in enterprise applications, cloud infrastructure, and data platforms. I focused on practical changes I could implement and evaluate, while keeping track of the work that still needs attention. The process helped me understand the importance of testing changes, working through unexpected issues, and recognizing when additional development is needed before an application can be considered complete.
